# 3D Part 1: World and Camera Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Draw the existing Sandbox Realms world in 3D with three.js. One camera runs from a top-down overview down to eye level. Every 2D map layer has a native 3D version, and the PixiJS 2D view stays as a fallback.

**Architecture:**
- `main.ts` stops talking to Pixi layers and the 2D `Camera` directly. It talks to one `WorldRenderer` interface, which has two implementations:
  - `Renderer2D` wraps today's Pixi code, with no behaviour change;
  - `Renderer3D` lives in `src/render3d/` and loads as the lazy `render3d` chunk.
- 3D layers plug into `Renderer3D` through a small `Layer3D` interface, so layer tasks touch separate files.

**Tech Stack:** TypeScript 7 strict, Vite 8 (rolldown manualChunks), three.js (pinned exact version), PixiJS 8 (2D), Vitest 5 (jsdom), Playwright 1.64 Chromium (SwiftShader WebGL).

**Spec:** `docs/superpowers/specs/2026-10-30-3d-world-design.md`: the sections "Part 1: 3D world and camera" and "Every map layer in 3D".

## Global Constraints

- No simulation changes. `GOLDEN_HASH 1357125849` is unchanged, and `node scripts/check-determinism.mjs` passes.
- **Budgets:**
  - main chunk ≤ 350 KiB gzip;
  - worker ≤ 250 KiB;
  - new `render3d` chunk ≤ 220 KiB gzip;
  - art caps are unchanged.
- three.js is imported only under `src/render3d/`. Nothing in the main chunk imports it statically.
- **Pin three.js:** to the exact version that `npm view three version` reports, if that version was released at least 2 weeks ago. Otherwise pin the newest release that is. Use `"three": "<x.y.z>"` with no caret, plus `@types/three` at the matching version.
- **Scale:**
  - 1 tile is 1 world unit and stands for 2 m;
  - eye height is 0.85 tile;
  - vertical scale is 0.04 tile per elevation unit, `ELEV_SCALE = 0.04`.
- **View rule:**
  - `?view=2d|3d` beats the saved choice, `localStorage['sr.view']`;
  - the saved choice beats the default;
  - default is 3D when WebGL2 works and `navigator.deviceMemory` is undefined or ≥ 4, otherwise 2D;
  - Safe Mode always means 2D.
- The Settings View switch reloads the page. The world survives through the normal autosave.
- Esc order: release pointer lock, then collapse the sheet, then disarm. Space still pauses.
- Existing e2e tests run in 2D. Only specs that opt in with `?view=3d` run in 3D.
- Local Playwright always runs with `--workers=1`. Only one heavy job runs at a time.
- Commits end with `Co-Authored-By: Claude Haiku 5.5 <noreply@anthropic.com>`. Agents commit on their own worktree branch. They do not merge or push.

## Review Focus

1. **Tiny maps and rebuilds:** a 64-tile map (`size=1`) and a map that changes size on New World. Chunks must rebuild with no leftover meshes. Owner: Task 4 test `rebuilds every chunk on setSide`.
2. **Ray misses or edge hits:** sky, beyond the map edge, a steep cliff face. These return null or the nearest valid tile and never throw. Owner: Task 3 picking tests.
3. **WebGL context lost and restored** in 3D. The renderer rebuilds its textures and meshes and nothing throws. Owner: Task 3 test `restores after context loss`.
4. **3D load failure:** the chunk fails to load or WebGL2 is missing. The game shows 2D plus the toast "3D view unavailable, showing 2D." Owner: Task 2 e2e `falls back to 2D when 3D fails`.
5. **Resize and rotation** (phone rotate, devtools resize) while at ground level. The camera keeps its tile and height, and nothing stretches. Owner: Task 3 test `resize keeps focus tile and height`.

**Interfaces:**
- `heights.ts`:
  - `export class HeightField { side: number; ground: Uint8Array; cover: Uint8Array; elev: Uint8Array; flags: Uint8Array; applyRows(rows: FrameRows): Set<number> /* dirty row indices */; heightAt(x: number, y: number): number /* bilinear, world units = elev * ELEV_SCALE */; }`
  - `export const ELEV_SCALE = 0.04;`
- `rig.ts`:
  - `export interface RigState { focus: TilePoint; height: number; yaw: number }`
  - `export function rigPose(s: RigState, side: number, groundAt: (x:number,y:number)=>number): { eye: [number,number,number]; target: [number,number,number]; pitch: number }`
  - Height runs from `EYE_HEIGHT = 0.85` above the ground under the focus up to `overviewHeight(side) = side * 1.1`.
  - Pitch is −90° (straight down) when `height ≥ 0.35 * overviewHeight`. It eases to −5° at `EYE_HEIGHT`, with smoothstep on log-height.
  - `export function zoomRig(s, factor, side, groundAt): RigState`: multiplies the height above ground, clamped to the range.
  - `export function panRig(s, dxTiles, dyTiles): RigState`: movement is relative to yaw.
  - `export function walkRig(s, forward, strafe, dtMs, speedTilesPerS): RigState`.
  - `export function rotateRig(s, radians): RigState`.
  - Focus is clamped to `[0, side]` on both axes.
- `pick.ts`: `export function pickTile(origin: [n,n,n], dir: [n,n,n], field: HeightField): TilePoint | null`. It steps the ray at 0.25 tile until it goes below `heightAt`, refines with 6 bisection steps, and returns the floored tile. It returns null for a sky ray, or a ray that leaves the `[0,side]` box before hitting.
- `layer.ts`:

```ts
export interface Layer3DContext { scene: THREE.Scene; camera: THREE.PerspectiveCamera; field: HeightField; renderer: THREE.WebGLRenderer; toScreen(x:number,y:number): ScreenPoint | null }
export interface Layer3D {
  readonly id: string;
  init(ctx: Layer3DContext): void;
  onRows?(dirtyRows: ReadonlySet<number>): void;
  onSide?(side: number): void;
  frame(input: FrameInput, ctx: Layer3DContext): void;
  dispose(): void;
}
```

  `Renderer3D` holds `layers: Layer3D[]`, registered in `renderer3d.ts` by one import line per layer. Tasks 4–8 each add their own line.
- `Renderer3D`:
  - `camera: CameraControl` drives `RigState`;
  - `screenToTile` is a raycast through `pickTile`;
  - `tileToScreen` projects the tile centre at `heightAt`;
  - it listens for `webglcontextlost` and `webglcontextrestored`, and on restore calls `onSide` on every layer to rebuild.
